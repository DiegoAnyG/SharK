# SharK working notes

Read this folder before starting work, and whenever a decision feels like one that has already
been made. It exists to maintain continuity, scientific rigor, and prevent repeating mistakes across sessions.

| File | What it holds | When to read it |
|---|---|---|
| `NEXT.md` | Handover: what to do next and what is unverified. Delete sections as they are done. | **First, every session.** |
| `RULES.md` | Hard constraints. Not negotiable. | Before writing any code. |
| `OBJECTIVES.md` | Where the project is going and what "done" means. | Before proposing work. |
| `DECISIONS.md` | Choices already made, with the reason and the cost. | Before re-opening a question. |
| `CHANGES.md` | Narrative of what changed in a session, and why. | To find out what state things are in. |
| `LOG.md` | Entry-per-change ledger, plus **Lessons** — mistakes that cost time. | Before assuming a cause. Read *Lessons* first. |

## How to use it

- A rule in `RULES.md` outranks anything convenient.
- If a decision in `DECISIONS.md` is being revisited, say so out loud and record the reversal
  there with the new reason. Do not quietly do the opposite.
- Anything that changes behaviour goes in `CHANGES.md` the same session it is done, not later.
- If something here is out of date, fix it here first, then act.

## Conventions for this folder

- English only, like the rest of the project.
- No absolute paths belonging to a person or a machine. Write `~/shark`, `<scratch dir>`,
  `<projects root>`, `<install prefix>`. These notes are expected to be readable by anyone.
- Dates are absolute (`2026-09-06`), never "yesterday" or "last week".
